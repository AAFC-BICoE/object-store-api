= Configuration

== File Storage

|===
|Property |Description

|`dina.fileStorage.implementation`
| `FS` (default) or `S3`

|`dina.fileStorage.root`
| Only required for `FS`. Represents the root folder in the context of the container/pod. The folder must exist.

|`dina.fileStorage.externalResourceMounts`
| Optional. Map of the mount points of externally hosted resources (`file:` URLs in `resourceExternalURL`). The key is the mount point recorded in `resourceExternalURL` (stored) and the value is where it is actually mounted in the context of the container/pod (active), so recorded URLs remain valid if the mount point changes. A `resourceExternalURL` is only resolved if it starts with a stored mount point; the rest of its path is resolved under the active mount point and must stay inside it once normalized and once symbolic links are resolved: for example, `file:///gpsc5/abc/../../etc/hosts` is rejected. Both mount points must be absolute paths. When not set, no external resource can be resolved. See the example below.

|`s3.*`
| Only required for `S3`. Represents the s3 specific configuration: `s3.endpoint`, `s3.port`, `s3.accessKey`, `s3.secretKey` and `s3.region` (`none` by default). When set, `s3.port` (`9000` by default) is appended to `s3.endpoint`: set it to an empty value if the endpoint already includes the port.
|===

=== External resource mounts

With the following configuration, `file:///gpsc5/abc/images/a.tif` is read from `/mnt/gpsc/abc/images/a.tif`. Map keys must be wrapped in `[]` to keep the `/`.

[source,yaml]
----
dina:
  fileStorage:
    externalResourceMounts:
      "[/gpsc5/abc]": "/mnt/gpsc/abc"
----

As an environment variable (e.g. in docker compose):

[source,yaml]
----
dina.fileStorage.externalResourceMounts[/gpsc5/abc]: /mnt/gpsc/abc
----

== Orphan Removal

The orphan removal cron job is responsible for identifying and removing orphan objects. Orphan objects are `object uploads` that do not have any matching file identifiers associated with `derivatives` or `metadata` objects.

[source,properties]
----
orphan-removal.expiration.objectMaxAge="20d"
orphan-removal.cron.expression="0 0 * * * *"
----

|===
|Property |Description

|`orphan-removal.expiration.objectMaxAge`
|The maximum age of objects to be considered for removal based on the `object upload` created on date. Objects older than this duration will be checked for orphan status. The duration should be specified using the ISO-8601 duration format, e.g., "20d" represents 20 days.

|`orphan-removal.cron.expression`
|The cron expression to schedule the orphan removal process. The process will run based on this cron expression to check for orphan objects if they have expired. The expression follows the cron format, e.g., "0 0 * * * *" represents running this check every hour of every day.
|===

If the `orphan-removal.cron.expression` variable is not specified (default), the orphan removal service will not be performed.
